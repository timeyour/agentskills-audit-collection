# AgentSkills Audit Workbench v0.1 Scope

This document freezes the v0.1 integration line so the repository stops expanding as a flat skill list and becomes an executable **delivery acceptance** skeleton.

## One-Line Product Promise

> Paste a URL or project → see what works, what is untrustworthy, what blocks launch, and what to fix first — with evidence, severity, copyable fix prompts, and retest steps.

## In Scope (v0.1)

| Area | Deliverable |
| --- | --- |
| Unified contract | `schemas/audit-report.schema.json` |
| Severity | Single `S0–S4` standard in `docs/severity-standard.md` |
| Evidence | `docs/evidence-levels.md` |
| Skill routing | `/audit` as orchestrator; sub-skills as modules — `docs/skill-routing-map.md` |
| Validation layout | `validation/templates/`, `cases/`, `artifacts/`, `golden/` |
| Workbench spec | `workbench/spec.md` + component contracts (no framework install required) |
| Golden examples | `validation/golden/audit-report.example.json`, `public-report.example.md` |
| Public report demo | Existing `reports/demo-site-audit.{md,html}` |

## Out of Scope (v0.1)

- Full Next.js/Vite workbench app with live Playwright wiring
- Automated five-pass runs end-to-end
- Login, payment, and destructive form submission automation
- Batch auto-audit of 200+ sites
- Scripts inside `.claude/skills/` (instruction-only rule unchanged)
- Replacing existing validation batch reports (they stay as historical proof)

## MVP User Journey

```text
1. User provides URL or local project path
2. Agent runs /audit (or focused sub-skills)
3. Output conforms to audit-report.schema.json
4. Workbench (future UI) or markdown template renders:
   - summary, feature inventory, flow log, issues, fix pack, regression
5. Optional export to public report (customer-facing)
```

## Acceptance Criteria (M0)

- [x] `/audit` documented as the only top-level audit entry
- [x] `/flow-test`, `/visual-qa`, `/deploy-check`, `/accept-five` documented as sub-flows
- [x] Every report field maps to schema; gaps use `UNKNOWN`, `NOT_APPLICABLE`, or `SKIPPED-SAFE`
- [x] `S0–S4` defined once in `docs/severity-standard.md` (not redefined per skill)
- [x] README links to v0.1 docs, schema, validation layout, and workbench spec

## Primary Audience (v0.1 bet)

**Customer / stakeholder acceptance reports first**, developer tooling second.

Reason: “Can this AI-built site be delivered?” is easier to differentiate and share than “another dev CLI.”
